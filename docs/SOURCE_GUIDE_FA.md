# راهنمای سورس App-Time

این فایل توضیح می‌دهد هر پوشه و فایل اصلی پروژه برای چه ساخته شده و معمولاً چه کسی/چه ابزاری آن را ایجاد یا ویرایش می‌کند.

## ریشه پروژه

### `settings.gradle.kts`
فایل تنظیمات سطح Workspace است. نام پروژه، ماژول‌های Gradle و Repositoryهای دریافت وابستگی‌ها را تعریف می‌کند. معمولاً توسط برنامه‌نویس ساخته و ویرایش می‌شود.

### `build.gradle.kts`
فایل Gradle سطح ریشه است. نسخه پلاگین Android و Kotlin را برای همه ماژول‌ها مشخص می‌کند. توسط برنامه‌نویس نگهداری می‌شود.

### `gradle.properties`
تنظیمات عمومی Gradle مثل حافظه JVM و AndroidX را نگه می‌دارد. فایل متنی پروژه است و توسط برنامه‌نویس قابل تغییر است.

### `.gitignore`
مشخص می‌کند چه فایل‌های محلی، خروجی‌های Build، رمزها و Keystoreها نباید وارد GitHub شوند. این فایل برای امنیت امضا اهمیت زیادی دارد.

### `version.json`
اطلاعات نسخه جاری و حداقل نسخه پشتیبانی‌شده را نگه می‌دارد. در آینده اپ می‌تواند این فایل را از منبع انتشار بخواند و نسخه جدید را تشخیص دهد.

### `README.md`
راهنمای کلی پروژه برای GitHub، Build، امکانات و توسعه آینده است.

## پوشه `app/`

این پوشه ماژول اصلی اپلیکیشن اندروید است.

### `app/build.gradle.kts`
مهم‌ترین فایل Build ماژول است. شامل Application ID، minSdk، targetSdk، versionCode، versionName، Compose، کتابخانه‌ها و تنظیمات Release Signing است.

### `app/proguard-rules.pro`
قواعد R8/ProGuard را نگه می‌دارد. فعلاً Minify خاموش است، اما با اضافه شدن Serialization یا کتابخانه‌های نیازمند Keep Rule این فایل استفاده خواهد شد.

## پوشه `app/src/main/`

سورس و منابع اصلی نسخه Production اینجا قرار دارند.

### `AndroidManifest.xml`
Application و Activity اصلی، مجوز اینترنت و اعلان و تنظیمات RTL را به سیستم اندروید معرفی می‌کند.

### `java/ir/asteam/apptime/MainActivity.kt`
نقطه ورود UI فعلی است. Theme، Drawer، Back Stack، داشبورد و Screenهای نسخه 1.1 داخل این فایل هستند. این فایل مستقیماً توسط برنامه‌نویس نوشته شده است.

### `res/values/strings.xml`
متن‌های Resource مثل نام برنامه را نگه می‌دارد. Android Studio و برنامه‌نویس هر دو ممکن است این فایل را ویرایش کنند.

### `res/values/themes.xml`
Theme سطح Window اندروید مثل Status Bar و Navigation Bar را مشخص می‌کند.

## پوشه `.github/`

این پوشه مربوط به امکانات GitHub است و داخل APK وارد نمی‌شود.

### `.github/workflows/android.yml`
GitHub Actions را تعریف می‌کند. بعد از Push روی `main`، پروژه را با JDK و Android SDK مناسب Compile می‌کند و خروجی Release را به‌عنوان Artifact نگه می‌دارد. این فایل توسط برنامه‌نویس/DevOps نوشته می‌شود، نه Android Studio.

## پوشه `docs/`

مستندات فنی پروژه است و داخل APK قرار نمی‌گیرد.

### `ARCHITECTURE_FA.md`
اصول معماری، آپدیت‌پذیری، ناوبری و توسعه آینده را توضیح می‌دهد.

### `SOURCE_GUIDE_FA.md`
همین فایل؛ برای اینکه با باز کردن سورس بتوان نقش پوشه‌ها را سریع فهمید.

## فایل‌ها و پوشه‌های تولیدشده خودکار که نباید Commit شوند

- `.gradle/` — Cache مربوط به Gradle
- `.idea/` — تنظیمات محلی Android Studio/IntelliJ
- `build/` و `app/build/` — خروجی‌های Compile و APK
- `local.properties` — مسیر SDK روی همان کامپیوتر
- `*.iml` — اطلاعات IDE
- `signing/*.jks` — کلید خصوصی امضای برنامه
- `signing/keystore.properties` — رمز و مسیر Keystore

این موارد ممکن است بعد از باز کردن پروژه روی لپ‌تاپ خودکار ساخته شوند و طبیعی است که در GitHub وجود نداشته باشند.

## قانون کامنت‌گذاری پروژه

هر فایل جدید باید حداقل موارد زیر را توضیح دهد:

1. هدف کلی فایل.
2. نقش کلاس/تابع یا بخش اصلی.
3. منطق غیر بدیهی مثل State، Navigation، Database Migration، Network و Signing.
4. دلیل استفاده از تنظیمات حساس یا غیرمعمول.
5. TODO یا محدودیت‌های موقت نسخه فعلی.

برای کدهای ساده و واضح، توضیح بلوکی کنار بخش مرتبط ترجیح داده می‌شود تا سورس از تعداد بیش از حد کامنت‌های تکراری ناخوانا نشود.
